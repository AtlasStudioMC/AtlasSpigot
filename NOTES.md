# 26.2 notes

26.2 is the flagship track and the one Leaf actively maintains. Its config has been audited
repeatedly; this file records the state of that audit, including the settings that were assessed
and **not** enabled, which is the part that's easy to lose.

Upstream base: `ver/26.2` (`e51867d` at the time of this pass).

## Where the config actually stands

Measured objectively rather than from memory: a stock config was generated by booting the released
`AtlasSpigot-26.2.jar` with no config directory, then diffed against the shipped one.

- `atlas-global.yml` covers **all 157 keys** the current build writes — nothing new has appeared
  upstream that we haven't seen.
- **18 settings** are tuned away from stock (async chunk send, async playerdata save, cache-biome
  ×3, DAB, dont-save-entity ×2, only-tick-items-in-hand, optimized-powered-rails, reduce-packets
  ×3, virtual threads ×2, mc-301114, B_LINEAR region format, xaero id).
- `paper-global.yml` carries 3 changes (chunk load/send rate uncapped, `max-joins-per-tick: 25`)
  and `paper-world-defaults.yml` 2 (`optimize-explosions`, `ALTERNATE_CURRENT` redstone).
- `server.properties` and Aikar's flags in `start.sh` are already tuned.

## Newly assessed this pass — all rejected

Seven performance-adjacent settings had never been documented either way. Every one was checked
against 26.2's own source, and none were enabled:

| Setting | Why not |
|---|---|
| `optimize-mob-despawn` | `@Experimental` |
| `optimize-waypoint` | `@Experimental` |
| `reuse-random-ticking-blockpos` | `@Experimental` |
| `optimize-no-action-time.disable-light-check` | `@Experimental` |
| `despawn-time.proactive-weak-loading-despawn` | `@Experimental` |
| `optimize-end-surface-gen` | Clean of annotations, but upstream's own config comment says *"May be incompatible with some datapacks that modify End world generation."* An explicit compatibility disclaimer is treated the same as `@Experimental` here. |
| `misc.lag-compensation` (TT20) | Not an optimization. Verified in `0166-TT20-Lag-compensation.patch`: it rescales fluid tick delays to wall-clock time when TPS drops, so fluids flow at real-time speed during lag. That *adds* work while the server is already struggling. It's a gameplay-consistency feature, and a reasonable one, but it does not belong in a performance config. |

While reading the TT20 patch, `fluidDelay(..., enableForLava, FluidTags.WATER)` looked like swapped
arguments. It isn't: the signature is `fluidDelay(level, pos, rawDelay, enabledForThisFluid,
oppositeTag)`, so the tag is deliberately the *other* fluid — used to skip compensation where water
and lava meet. Recorded here so the next person doesn't re-raise it.

## The config is at its safe ceiling

Every remaining Leaf toggle on this track is one of: `@Experimental`, carrying an explicit upstream
incompatibility warning, blocked on an open upstream issue, or a deliberate gameplay change. There
is no more free performance in `atlas-global.yml`.

Further gains require accepting a gameplay or compatibility tradeoff. These are **deliberately not
applied**, and are listed so the choice stays with the server owner:

- **`spigot.yml` entity activation ranges** — currently at Spigot defaults. Lowering them is the
  single biggest classic win, and the single most likely thing to break mob farms and make distant
  mobs freeze.
- **`paper-world-defaults.yml` `hopper.disable-move-event`** — large win on hopper-heavy servers,
  but it stops firing `InventoryMoveItemEvent`, which shop and economy plugins rely on. That
  directly contradicts "your plugins keep working".
- **`gale-global.yml` `increase-time-statistics`** — batches statistic increments. `PLAY_TIME` and
  `TOTAL_WORLD_TIME` stay exact, but `CROUCH_TIME`, `TIME_SINCE_DEATH` and `TIME_SINCE_REST` become
  sampled approximations, since they're only checked on the interval tick. `TIME_SINCE_REST` drives
  phantom spawning.
- **View and simulation distance** — already at 6/4, which is well below vanilla. Lowering further
  trades visible world for TPS.

## Not benchmarked

The published benchmark numbers are from 1.21.4. No measurements have been taken on 26.2, so no
performance figures are claimed for this track.
